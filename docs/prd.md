# PRD - 个人博客 CMS

## 1. 产品概述

本项目旨在构建一个基于 Next.js 的个人博客 CMS，用于替代 WordPress，满足个人长期写作、内容管理、对外展示和持续扩展的需求。

系统不仅要能发布博客，还要具备完整后台管理能力，并且在技术架构上适合作为全栈项目实践和简历展示作品。

## 2. 背景与问题

现有常见方案各有明显短板：

- WordPress 功能完整，但整体偏重，维护成本高，技术栈分裂，不利于作为现代全栈项目实践。
- 纯静态博客方案足够轻，但缺乏后台管理、评论审核、用户权限和内容运营能力。
- Headless CMS + 前端分离方案灵活，但对个人项目来说部署与维护复杂度偏高。

因此需要一个单体全栈方案，兼顾：

- 内容发布效率
- 后台可管理性
- SEO 能力
- 技术可扩展性
- 部署可控性

## 3. 产品目标

### 3.1 核心目标

- 替代 WordPress 作为个人博客与 CMS 系统
- 支持长期使用，而不是一次性练手项目
- 提供完整后台管理系统
- 对搜索引擎友好，具备 SSR / SSG / ISR 能力
- 为未来 AI、搜索、缓存等能力扩展预留空间

### 3.2 项目型目标

- 作为全栈学习项目覆盖从前端到后端、数据库、鉴权、部署的完整链路
- 作为简历展示项目，体现架构设计、工程拆分与生产思维

## 4. 目标用户

### 4.1 管理员 / 博主

系统的核心使用者，负责：

- 撰写与发布文章
- 管理分类、标签、评论
- 管理站点设置和用户权限
- 查看后台内容状态与运营数据

### 4.2 普通登录用户

主要用于：

- 登录后发表评论
- 参与互动
- 在未来可扩展为协作者或作者角色

### 4.3 游客访客

主要用于：

- 浏览博客内容
- 按分类、标签、搜索访问内容
- 在允许的情况下发表评论

## 5. 核心使用场景

### 5.1 内容生产场景

- 管理员进入后台创建文章
- 使用 Markdown 编辑正文
- 设置标题、slug、摘要、封面图、SEO 信息
- 文章先保存为草稿，确认后再发布

### 5.2 内容消费场景

- 访客访问首页浏览文章列表
- 进入文章详情页阅读内容
- 通过分类、标签、搜索页继续发现内容

### 5.3 内容治理场景

- 管理员在后台审核评论
- 管理员管理分类与标签体系
- 管理员管理普通用户及其权限状态

## 6. MVP 范围

MVP 需要覆盖以下功能：

### 6.1 用户与权限

- 登录能力
- 基于角色的权限控制（RBAC）
- 基础角色：`admin` / `user` / `visitor`

### 6.2 文章系统

- Markdown 编辑
- 草稿 / 发布状态
- slug 管理
- SEO meta 字段
- 封面图字段

### 6.3 分类与标签

- Category 一对多管理文章
- Tag 多对多关联文章
- 支持前台分类页与标签页

### 6.4 评论系统

- 文章评论
- 支持嵌套评论
- 支持评论审核开关

### 6.5 后台管理系统

- 文章管理
- 评论管理
- 分类管理
- 标签管理
- 用户管理

### 6.6 前台博客系统

- 首页
- 文章详情页
- 分类归档页
- 标签归档页
- 搜索页

### 6.7 SEO 基线

- metadata
- sitemap
- robots.txt
- 对公开内容的 SSR / SSG / ISR 支持

## 7. 非功能性要求

### 7.1 SEO

- 所有公开页面可生成规范 metadata
- 文章页支持 Open Graph 信息
- 支持 sitemap.xml 和 robots.txt
- URL 结构稳定且语义化

### 7.2 可维护性

- 工程结构清晰，模块边界明确
- 产品与技术文档可长期维护
- 数据结构可迁移、可演进

### 7.3 可扩展性

未来应能较低成本接入：

- AI 写作辅助
- 搜索引擎升级
- Redis 缓存
- 图片存储迁移到对象存储
- 站内统计与订阅能力

### 7.4 部署与运行

- 支持 Docker 部署
- 支持 PostgreSQL 独立运行
- 后续可以接入 Redis 等附属服务

## 8. 非目标

当前阶段不强制纳入 MVP 的内容：

- 多租户博客系统
- 富文本编辑器优先于 Markdown
- 复杂工作流审批系统
- 多语言国际化
- 对外开放 API 平台
- 高并发场景优化

这些能力可以在后续阶段扩展，但不应阻塞首版系统落地。

## 9. 成功标准

首版项目达到以下标准，可视为 PRD 层面的阶段性成功：

- 能完成从后台写作到前台展示的完整闭环
- 管理员可以独立完成文章、评论、分类、标签、用户的基础管理
- 前台页面对 SEO 友好，公开内容可被搜索引擎正确抓取
- 技术结构足够清晰，可继续向生产级能力演进
- 文档足够完整，能指导后续正式开发，而不是重新讨论需求
